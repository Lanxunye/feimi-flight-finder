# 飞觅 Feimi

**面向中国国内航班的本地优先比价与价格监控 WebUI。**

飞觅将城市与机场选择、航班检索、转机筛选、双次报价对比、收藏管理和 iMessage 价格提醒放在同一个界面中。用户检查行程与报价后，跳转到原购票平台购买；项目本身不处理订票、支付和出票。

这是一个围绕个人出行需求构建的实验性项目，完整运行流程主要面向 macOS。它采用周期性查询，不是航空公司的实时价格推送，也不承诺覆盖全部航班或找到市场最低价。

> **版本说明**：本次更新同步多收件地址、独立收藏夹、收藏复制和移动、通知平台信息与收藏起降时刻等本地迭代功能。下列功能以当前分支源码为准，已有安装需要更新前后端才能使用。

## 项目背景与开发方式

机票选择不只取决于价格，也涉及衔接时间、总行程和跨日。同一航班在不同平台、不同查询时刻的报价还可能变化。飞觅希望把这些信息集中起来，让用户自己比较，再到原平台确认余票与最终价格。

项目大部分代码和功能迭代由 AI 编程助手辅助完成，采用通常所说的 **Vibe Coding** 方式：维护者提出需求、决定流程、实际操作验收，再根据结果调整实现。

这是一次从真实个人需求出发的 AI 辅助开发实践，尚未完成全面工程审查、跨平台测试或大规模运行验证。本地验收通过不等于对所有航线、账户、系统版本和未来平台页面的兼容承诺。

## 从查询到提醒

```text
选择城市、日期和可选转机地
  → 多来源查询并规范化结果
  → 按航班号和起降时间匹配两次报价
  → 对比价格、时长和转机方案
  → 收藏并选择报价基准
  → 约每 30 分钟复查价格
  → 价格变化时发送 iMessage，附购票链接
```

## 功能与版本状态

### 航班搜索与基础功能

- **城市与机场选择**：支持城市、区县检索及附近机场选择；距离按经纬度计算，不是道路距离或地面交通耗时。
- **国内航班查询**：组合携程、去哪儿、飞猪相关适配与 Crawl4AI 辅助抓取，返回结果取决于来源可用性。
- **转机查询**：支持指定转机地；未指定转机地且没有直飞结果时，尝试单次转机方案。
- **通程筛选**：依据来源明确标注的通程或相关保障信息，不仅凭同航司推断。
- **双次报价对比**：同航班两次报价并列展示，允许价格不同，供用户人工选择。
- **行程展示与排序**：显示航班号、起降时间、总时长和转机余量；跨日方案默认折叠。
- **收藏管理**：关注置顶、展开收藏夹、批量取消、收藏历史和历史删除。
- **价格提醒**：约每 30 分钟检查收藏航班，启用提醒时自动发送测试 iMessage。
- **隔离登录窗口**：WebUI 提供携程、去哪儿、美团入口；登录入口不等于已经接入报价。
- **本地退出**：停止飞觅相关网页、抓价、提醒和专用浏览器服务。

### 本次同步的收藏与通知更新

- 多提醒号码或邮箱，以及按收件地址区分的独立收藏夹。
- 跨收件地址复制和移动收藏；复制后的收藏可独立取消。
- 提醒正文增加明确的购票平台名称。
- 展开的收藏和收藏历史增加出发、到达时刻。
- 携程专用浏览器取消开机及启动飞觅时自动打开，改为手动打开。

旧的单收件地址状态会在加载时迁移到多收件地址结构。升级前建议备份本机状态文件；通知仍依赖有效的 iMessage 环境。

## 数据来源与工作原理

项目通过来源适配器把不同格式转换为统一航班结构，并没有一个覆盖所有平台的统一官方机票分销 API。

| 来源或组件 | 用途 | 依赖与边界 |
| --- | --- | --- |
| 携程 | 从专用 Chrome 搜索流程捕获结构化航班响应 | 需要可用的本地浏览器会话，用户人工完成登录或验证码 |
| 去哪儿 | 结合搜索响应与页面实际显示的票价解析 | 原始响应部分价格存在混淆，依赖页面渲染和分页处理 |
| 飞猪 FlyAI | 通过 `@fly-ai/flyai-cli` 查询航班 | 需要相应密钥、服务权限及有效返回 |
| Crawl4AI | 辅助抓取未登录网页 | 自动化访问不一定成功，不保证取得报价 |
| 美团 | 隔离浏览器登录入口 | 价格适配尚未完成验证，不作为已验证报价来源 |
| 通义千问（可选） | 联网检查航班、机场、日期的明显语义冲突 | 不生成或修改票价，不构成价格认证 |

携程与去哪儿使用独立 Chrome 配置目录。后端通过 Playwright 和本机 Chrome 调试接口连接专用浏览器。适配器不主动提取账号密码或 Cookie；登录会话仍由浏览器保存在本机，因此浏览器资料目录也需要保护。

### 双次查询的含义

主要流程对同一来源查询两次，按航班号和起降时间匹配行程。两次价格可以不同，用户可以选择其中一个作为收藏基准。

**双次查询不是两个独立平台的交叉认证，也不是锁价。** 它能减少部分错配，但不能保证舱位、退改条件、附加费用和最终支付价格保持不变。证据不足时，不使用模型生成或演示价格填补。

## 行程筛选规则

- 总行程不超过 **16 小时**。
- 普通转机至少预留 **120 分钟**。
- 携程适配器中，来源明确标记保障的部分通程行程可使用 **90 分钟**最低衔接规则，不适用于所有转机。
- 当前主要处理直飞与单次转机，未承诺多次转机路线搜索。
- 跨日方案默认折叠，由用户自行展开。
- 综合排序权重为价格 **55%**、总时长 **35%**、转机次数 **10%**，不是只按最低价排序。
- 应用层不额外限制最终方案数，但结果受来源覆盖、分页、访问状态和筛选条件影响。

## 收藏与价格监控

收藏时保存购票平台、日期、航班号、起降时间、购票链接及选定报价。定时任务重新搜索，只匹配同一平台、同一航班号与起降时间的行程，再与上次成功通知所使用的基准比较。

- 计划检查间隔为 **1800 秒**，不是秒级实时推送。
- 价格上涨或下降时通知，未变化时不重复通知。
- 查不到匹配航班时跳过，不把缺失结果当作降价或零价。
- 成功发送后推进价格基准，发送失败不按成功处理。
- 已过去的出行日期不继续参与检查。
- 检查依赖 Mac 开机、唤醒、联网，以及本地服务和平台会话有效；休眠或退出会影响检查。

通知包含行程、价格变化、购票平台名称和购票链接。多收件地址分别管理收藏；复制保留来源收藏，移动则改变所属收件地址。

## iMessage 依赖与设备支持

消息发送使用上游 [imsg](https://github.com/openclaw/imsg)，明确调用 `--service imessage`，不自动回退为普通短信。

**发送端**需要运行飞觅的 Mac、可正常发送 iMessage 的系统“信息”应用，以及安装可用的 `imsg`。需要相应自动化权限；上游工具涉及读取消息数据库的功能还需要完全磁盘访问权限，具体以安装版本和启动方式为准。

**接收端**需要已启用 iMessage、可通过所填号码或 Apple 账户邮箱收件的 Apple 设备。普通手机号本身不保证具备 iMessage 接收能力。当前没有通用短信、邮件、微信或 Android 推送替代通道。

| 环境 | 当前状态 |
| --- | --- |
| macOS | 完整本地运行与部署的主要目标，依赖 Chrome、Node.js、Python 和 LaunchAgent |
| iPhone / iOS | 可作为 iMessage 收件端；没有原生 iOS 应用，不能独立运行抓价与监控 |
| iPad / 其他 Apple 设备 | 依赖其 iMessage 收件能力，未完成逐设备兼容测试 |
| Windows | 尚未适配完整运行、启动管理与消息链路 |
| Linux | 尚未验证完整部署和消息发送流程 |
| 在线 WebUI | 界面可与本地服务分离，不代表云端已经托管本机登录态、抓价或消息发送 |

尚未建立完整系统兼容矩阵，**没有经过验证的最低 iOS 版本要求**，也不承诺全部 macOS 版本和 Mac 硬件均兼容。

## 地域范围

界面、位置数据与实际使用流程主要围绕中国大陆城市、机场和国内航班构建。国际航线、港澳台及海外平台、多币种和跨时区行程未完成全面适配与验证。

机场与城市数据来自生成时的数据集，不能保证始终覆盖最新通航变化。“附近机场”依据地理距离推荐，并不代表一定有可售航线。

## 本地开发

### 环境要求

- macOS 和已安装的 Google Chrome。
- Node.js **>=22.13.0**。
- Python **3.12**。
- 启用通知时另需 `imsg` 和可用的“信息”应用。

### 安装依赖

从项目根目录运行：

```bash
npm install
python3.12 -m venv .venv
.venv/bin/python -m pip install -r crawler-service/requirements.txt
```

### 启动后端

在单独终端中，从项目根目录运行：

```bash
cd crawler-service
../.venv/bin/uvicorn main:app --host 127.0.0.1 --port 8001
```

需要飞猪或模型检查时，在启动后端的运行环境配置相应密钥。携程、去哪儿还需要准备隔离 Chrome 会话；仅启动 API 不会自动获得已登录浏览器。详见 [后端说明](crawler-service/README.md)。

### 启动 WebUI

在另一个终端中，从项目根目录运行：

```bash
FLIGHT_CRAWLER_URL=http://127.0.0.1:8001 npm run dev
```

打开终端输出的本地地址。服务未配置、不可用或证据不足时，不以模拟行情代替报价。

### 可选环境配置

| 变量 | 用途 |
| --- | --- |
| `FLIGHT_CRAWLER_URL` | WebUI 连接本地抓价服务的地址 |
| `FLYAI_API_KEY` | 飞猪 FlyAI 凭据 |
| `DASHSCOPE_API_KEY` | 可选通义千问检查凭据 |
| `CTRIP_CDP_URL` | 携程专用 Chrome 的本机调试接口 |
| `FEIMI_RUNTIME_STATE_DIR` | 本地状态存储目录 |
| `IMSG_PATH` | 指定 `imsg` 可执行文件 |

密钥通过本地运行环境提供，不应提交到仓库。桌面启动脚本可从本机 `secrets.env` 读取指定密钥；普通开发启动不会自动读取该文件。外部服务的权限、可用性与费用由相应服务决定。

### 构建与检查

```bash
npm run build
npm run lint
npm test
```

从项目根目录运行后端已有测试：

```bash
cd crawler-service
../.venv/bin/python -m unittest discover -p 'test_*.py'
```

这些检查不能代替真实平台查询、登录和消息送达验证。

## macOS 部署与退出

项目提供 `launchd/` 模板与 `scripts/` 启停脚本：

```bash
zsh scripts/install-launch-agents.sh
```

**该脚本只安装启动项模板和相关脚本，不是完整的一键安装器。** 还需要在目标运行目录准备后端、Python 环境、前端构建产物与运行依赖、Chrome 等组件。

桌面安装版默认目录为 `~/Library/Application Support/Feimi`。用户服务分别管理 WebUI、抓价接口、价格检查和各平台专用浏览器。携程专用浏览器默认不随开机或飞觅启动自动打开，可从 WebUI 手动启动；这项调整不改变其他平台浏览器的启动设置。

WebUI 的“退出飞觅”及 `scripts/feimi-stop.sh` 用于停止飞觅相关服务。**关闭网页标签页不等于停止后台任务。** 部分浏览器不允许网页自行关闭普通标签页，可手动关闭退出后的页面。

## 本地数据与外部请求

- 收藏、通知设置与收件地址保存在本机。桌面版状态文件通常位于 `runtime-state/price-alerts.json`，写入权限设为 `0600`。
- 登录会话由专用 Chrome 配置目录保存，不要公开这些目录。
- 航班查询仍需要访问外部平台或查询服务。
- 启用模型检查后，相关查询和候选航班信息会发送给模型服务。“本地优先”不等于完全离线或没有外部数据传输。
- `.gitignore` 排除了常见环境文件、运行资料与构建产物；公开前仍需核对实际提交内容。

## 已知限制

- 平台页面、响应结构和票价展示可能变化，适配器需要维护。
- 登录失效、验证码、网络故障或访问限制可能导致没有结果。
- 多来源接入不等于各来源覆盖相同；缺少某平台结果不代表该平台价格更高。
- 没有官方全量航班覆盖、实时库存或出票能力承诺。
- 最终票价与余票以原平台出票页面为准；使用前应确认相关平台的服务条款、访问规则与数据授权。
